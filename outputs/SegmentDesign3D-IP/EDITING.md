# パーツの形状・位置編集

分割結果、または現在選択しているCCS補正結果の各パーツを、個別に拡大・縮小します。接続境界がある場合は、接続点を合わせる平行移動も適用します。
各パーツのX/Y/Z移動も指定できます。手動移動は拡大縮小と自動追従の後に加え、他のパーツへ伝えません。接続位置を自由にずらすための操作です。
編集用の入力はAPIから取得済みの `parts.npz` と対応表です。編集の操作でGPU推論やGeminiを呼び直しません。

## 操作

「パーツ編集」に、パーツ数に合わせたスライダーと3D表示が現れます。パーツを選択してからスライダーを出す操作は不要です。数が多いときはスライダーの一覧をスクロールできます。

- ラベルはLLMが作成してInstruct-Particulateに渡した英語の `name` です。
- 各倍率の初期値は1.00、範囲は0.10～3.00、刻みは0.01です。XYZを同じ倍率で変えます。
- 同名パーツがあっても、対応は `part_id` で保持します。
- 面が割り当てられなかったパーツも一覧に残り、「面なし」と表示してスライダーを無効にします。
- 各パーツの「X 移動」「Y 移動」「Z 移動」で、そのパーツだけを平行移動します。初期値は全軸0です。入力モデルの座標軸・座標単位を使い、mmなどの単位は推定しません。
- 移動範囲は元モデル全体の最大寸法をRとして各軸 `-R～+R`、刻みは `R/1000` です。範囲は倍率を変えても変わりません。画面に実際の値を表示します。
- 「基準パーツ（拡大縮小の位置を固定）」で、自動追従の基準を選びます。初期値は先頭の非空パーツです。このパーツもX/Y/Z移動で手動移動できます。
- 「接続位置に追従」は初期状態でオンです。接続先のパーツが、変形後の接続点へ平行移動します。オフにすると以前の各パーツの中心を固定したスケーリングになります。
- 追従がオンでも、X/Y/Zの手動移動では接続点を維持しません。親パーツを動かしても、子パーツにその手動移動を加えません。移動後のずれは接続点と診断表に反映します。
- 「接続点を表示」で丸印を切り替えられます。緑は両側の点が一致した状態、橙とその間の線はずれがある状態です。
- 「検出した接続関係」には英語パーツ名、追従に使用した接続、接続点間の距離を表示します。距離は入力モデルの座標単位で、mmなどの物理単位は推定しません。
- 左上の回転矢印「編集を初期化」は全倍率を1.00、全移動量を0に戻します。隣のアイコンはモデル全体が入る位置にカメラを合わせます。
- すべての3D表示はTurntable Rotationです。指定した上方向（±X/±Y/±Z）を軸としてドラッグで回転し、ホイールでズームできます。パーツ編集中の表示も同じ上方向を維持し、画面をひねる回転は行いません。
- 「編集後 GLB」から、変更後の頂点を持つ独立パーツのGLBを保存できます。
- 編集後に「一つのMeshへ結合」を押すと、元の接続情報を使って境界を橋渡しし、面色を残した一つのMeshを下段に表示します。「結合後 GLB」「結合後 NPZ」から保存できます。

## 中心と計算式

承認した方針どおり、中心はパーツを囲む軸に平行な直方体（AABB）の中心です。ボクセル化や頂点の平均は使いません。

```text
center = (元頂点の各軸の最小値 + 元頂点の各軸の最大値) / 2
編集後の頂点 = center + 倍率 × (元頂点 - center)
```

この計算の後、接続への追従がオンなら各パーツに自動の平行移動を加え、最後に各パーツ固有のX/Y/Z移動を加えます。

```text
最終頂点 = center + 倍率 × (元頂点 - center) + 自動追従の移動量 + 手動のX/Y/Z移動量
```

常に元の頂点から計算するので、編集は累積しません。全倍率を1.00、全移動量を0に戻すと元の形状と位置に戻ります。手動移動は倍率で拡大されません。

## 接続の検出と追従

`connections.py` が、NPZの全体頂点・面・各面の所属を使って接続を検出します。

1. 座標が完全一致する頂点を、境界検出のときだけ同じ頂点とみなします。UVや法線の都合で複製された頂点にも対応します。編集用の頂点配列は結合しません。
2. 2面が共有するエッジで、面のパーツIDが異なるものを接続境界とします。点だけの接触、微小な隙間、近いだけの別メッシュには接続を作りません。3面以上が共有する異種パーツ間エッジは曖昧なため除外して通知します。
3. パーツの組ごとに、境界エッジの連結成分を分けます。離れた接続領域を一つの中心へまとめません。
4. 各領域で、エッジ中点を長さで重み付けした平均を接続点にします。細かく分割された頂点が多い場所へ偏るのを避けます。
5. 境界長の長い接続から優先して、循環しない接続グラフを作ります。選択した基準パーツから親→子の順に位置を計算します。

```text
親側の接続点 = 親の元中心 + 親倍率 × (元接続点 - 親の元中心) + 親の移動量
子側の仮接続点 = 子の元中心 + 子倍率 × (元接続点 - 子の元中心)
子の移動量 = 親側の接続点 - 子側の仮接続点
```

子自身もスケーリングされている場合を含め、両側の接続点を合わせます。子の移動を孫にも伝えます。
基準パーツにつながらないグループは、それぞれID最小の非空パーツを自動追従の基準にします。空パーツは接続先にも基準にも使わず、移動スライダーも無効にします。

輪状の接続や同じ組の複数接続がある場合、平行移動だけで全条件を満たせないことがあります。優先した接続以外を無視したまま成功扱いにせず、通知と表・点の表示で残りのずれを確認できるようにしています。全接続を同時に最適化する機能はありません。
境界検出は幾何的な隣接を使うため、セグメントの誤った飛び地による境界も候補になります。接続点の自動判定が意図どおりか、表示で確認してください。

## ブラウザ表示とPythonの対応

1. Pythonの `editing.py` がNPZからパーツごとの頂点・面と中心を読み込みます。
2. スライダーのドラッグ中はThree.jsが同じ中心・倍率・接続グラフで拡大縮小・位置の追従・手動移動を描画します。毎フレームのPython実行やGLBの再生成は不要です。
3. ドラッグを離すと倍率と移動量をStreamlitへ渡します。Pythonは `follow_connections()`（追従オフなら `scale_parts()`）の後、`translate_parts()` で手動移動を適用します。
4. Pythonで計算したパーツは `st.session_state["part_editing"]["edited_parts"]` に保持します。今後の形状編集処理から利用できます。
5. 接続の情報・基準パーツ・移動量・接続点のずれは `st.session_state["part_editing"]["connections"]` に保持します。「編集後 GLB」には位置補正済みの頂点と、この情報をシーンのメタデータに保存します。接続点の丸印や補助線はGLBの形状へ追加しません。
6. 手動移動は `st.session_state["part_editing"]["offsets"]` に保持します。接続メタデータの `automatic_translations` が自動追従、`manual_translations` が手動移動、`translations` が合計です。GLBの最終頂点と再結合にも手動移動を反映します。

編集元はモデルID・パーツ構成ID・分割ID・NPZ内容で識別します。別の分割結果やCCS補正結果へ切り替えると倍率と移動量を初期化します。
モデル・要求文・向きなどの変更で分割結果が無効になると編集状態も破棄します。ページを再読み込みした場合も倍率は永続保存されません。

入力GLB、分割済みGLB、NPZを上書きしません。元データは保持され、編集済みモデルはダウンロードしたGLBへ保存されます。
接続点が一致しても、倍率が異なる境界の幅や形状は一致しない場合があります。局所変形、干渉回避、切断面の穴埋め・水密化は行わないため、隙間や重なりが生じることがあります。

## ボタンによるメッシュの再結合

スケーリング・位置追従・X/Y/Zの手動移動を適用した後の形状を使います。結合はボタンを押した時点の結果として保持し、スライダー・基準パーツ・追従設定を変えたときは古い結合結果を非表示にします。結合ボタンをもう一度押して更新してください。接続点の表示切り替えでは結合結果を保持します。

`rejoining.py` が以下の処理を行います。

1. NPZの `source_vertex_indices` と `source_face_indices` で、各パーツの頂点・面を元モデルへ対応づけます。対応情報が欠ける場合はボタンを無効にします。
2. 元の頂点位置が同じだったコピーについて、編集後も位置が一致するものを統合します。数値誤差としてモデル全体の対角長の `1e-10` を許容します。元の対応が異なる近接頂点を距離だけで結合しません。
3. 元は辺を共有していた異なるパーツの間で、境界が離れた部分に三角形を追加します。位置追従のために選択した接続グラフだけでなく、元の共有境界全体を使います。UVや法線用に座標が完全一致した元頂点は、既存の接続検出と同様に同じ位置として扱います。
4. 接続帯の両側に既存面と逆向きの辺を作り、面の向きをそろえます。3パーツ以上の接点に生じた、同じ元頂点由来の小さな閉じた境界には接続面を追加します。
5. 元の面は順序・位置・パーツ色を維持します。追加した接続帯の2三角形には、隣接する両側の色を1枚ずつ割り当てます。接点の補助面も隣接パーツの色を継承します。

確認用の処理です。面の交差や重なりは修正しません。一般的な穴埋め、元形状の開口部の閉鎖、ブーリアン和は行いません。3面以上が共有する曖昧な元境界には橋渡し面を自動生成しません。頂点の統合で不要になる接続面や面積ゼロの接続面は追加しません。

「Mesh数：1」は一つの頂点・面配列にまとめたことを表します。元から離れたメッシュ間に新しい接続は作らないため、連結成分が複数残ることがあります。画面に成分数と元面・接続面の数を表示します。水密化や3Dプリントへの適合を保証する処理ではありません。

- **結合後GLB**：glTF上のMesh一つ・ノード一つとして保存します。同じ頂点座標の配列を使い、パーツ色ごとに面をマテリアルのグループへ分けます。面色を頂点で平均して混ぜる処理は行いません。読み込みソフトによっては、このグループを別々の形状として扱う場合があります。
- **結合後NPZ**：統合済みの `vertices`、`faces`、面ごとの `face_part_ids`、`face_colors`、`source_face_indices`、`is_bridge` を保存します。追加面の `source_face_indices` は `-1`、`is_bridge` は `True` です。Pythonで結合した頂点の共有関係をそのまま読み込めます。

元の入力・分割ファイルと、編集中の独立パーツは上書きしません。GLBとNPZは画面からダウンロードしたファイルへ保存されます。

## 起動と変更箇所

通常のStreamlit起動方法は[README.md](README.md)と同じです。起動中なら画面を再読み込みしてください。
既存のPython依存だけで動きます。WSL側のファイル更新、Node.jsのインストール、フロントエンドの再ビルドは通常の起動に不要です。

`scale_component/dist/` にビルド済みJavaScriptとHTMLを同梱しています。ブラウザUIのソースを変更するときだけ、Node.jsとpnpmで再ビルドします。

```powershell
cd scale_component
pnpm install --frozen-lockfile --store-dir node_modules/.pnpm-store --node-linker hoisted --package-import-method copy
node build.mjs
node --test tests/connection_solver.test.mjs
node --test tests/editor_args.test.mjs
node --test tests/turntable_controls.test.mjs
```

`src/editor.js` が動作、`dist/index.html` がレイアウト、`build.mjs` がJavaScriptと第三者ライセンス一覧の生成を担当します。
依存はロックファイルで固定しています。Three.js（MIT）、Streamlit Component Library（Apache-2.0）、Lucide（ISC）のライセンスと依存ライブラリの通知を `dist/THIRD_PARTY_LICENSES.txt` に同梱しています。

更新前のWindows UIが移動量や範囲を送らない場合も、旧データの表示は継続できます。その場合、移動スライダーを無効にしてUI再起動の案内を表示します。Windows側のStreamlitを停止・再起動してから、ブラウザを再読み込みしてください。WSL側の再起動や変更は不要です。

JavaScriptはビルド内容のハッシュを付けたURLで配信し、Python側のコンポーネント名にも同じハッシュを使用します。ビルド後にWindows UIを再起動すると、新しいコードを読み込みます。

参照：[Three.js OrbitControls](https://threejs.org/docs/#examples/en/controls/OrbitControls)、[Streamlit components](https://docs.streamlit.io/develop/concepts/custom-components/intro)。
