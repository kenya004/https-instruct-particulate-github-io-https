# パーツの形状・位置編集

分割結果、または現在選択しているCCS補正結果の各パーツを、個別に拡大・縮小します。接続境界がある場合は、接続点を合わせる平行移動も適用します。
各パーツを3方向に移動できます。初期基準は接続断面の近似平面で、平面内のU/Vと法線Nを使います。入力X/Y/Zへも切り替えられます。手動移動は拡大縮小・自動追従・境界なじませの後に加え、他のパーツへ伝えません。初期値の全体移動は接続位置を自由にずらし、断面固定移動は共有境界を残して遠い頂点ほど大きく動かします。
編集用の入力はAPIから取得済みの `parts.npz` と対応表です。編集の操作でGPU推論やGeminiを呼び直しません。

## 操作

「パーツ編集」に、パーツ数に合わせたスライダーと3D表示が現れます。パーツを選択してからスライダーを出す操作は不要です。数が多いときはスライダーの一覧をスクロールできます。

- ラベルはLLMが作成してInstruct-Particulateに渡した英語の `name` です。
- 各倍率の初期値は1.00、範囲は0.10～3.00、刻みは0.01です。XYZを同じ倍率で変えます。
- 同名パーツがあっても、対応は `part_id` で保持します。
- 面が割り当てられなかったパーツも一覧に残り、「面なし」と表示してスライダーを無効にします。
- 「移動方向の基準」の初期値は「断面の近似平面」です。「断面U 移動」「断面V 移動」「法線N 移動」で、そのパーツの移動量を指定します。3方向とも初期値0です。断面がないパーツは入力XYZを使い、全パーツを入力XYZへ切り替えることもできます。入力モデルの座標単位を使い、mmなどの単位は推定しません。
- 「パーツごとの移動方法」を開くと、英語パーツ名ごとに全体移動・断面固定移動を選べます。初期値は全体移動です。固定移動の遷移範囲はパーツごとに初期20%、範囲1～100%です。断面や面がないパーツでは選択できません。設定変更時は現在の移動量を新しい重みで再適用します。
- 「移動軸を表示」で、赤U・緑V・青Nの矢印を表示します。入力XYZの場合は同じ色順でXYZです。複数の接続があるパーツでは「移動軸の基準接続」から選びます。初期値は境界が最も長い接続で、同長なら接続ID順です。
- 移動範囲は元モデル全体の最大寸法をRとして各軸 `-R～+R`、刻みは `R/1000` です。軸を変更して既存の移動量が範囲を超えた場合、その値を保持できるまで表示範囲を広げます。軸の切り替え自体では形状・位置を変更しません。
- 「基準パーツ（拡大縮小の位置を固定）」で、自動追従の基準を選びます。初期値は先頭の非空パーツです。このパーツもX/Y/Z移動で手動移動できます。
- 「接続位置に追従」は初期状態でオンです。接続先のパーツが、変形後の接続点へ平行移動します。オフにすると以前の各パーツの中心を固定したスケーリングになります。
- 全体移動では、追従がオンでも手動移動時の接続点を維持しません。断面固定移動では移動直前の共有境界を保持します。どちらも親パーツの手動移動を子へ加えません。実際の境界位置は接続点と診断表に反映します。
- 「接続点を表示」で丸印を切り替えられます。緑は両側の点が一致した状態、橙とその間の線はずれがある状態です。
- 「境界なじませを適用するパーツ」で、境界付近の拡大縮小を調整するパーツを複数選べます。初期状態は未選択です。「境界なじませの範囲（%）」は初期値20%、範囲1～100%です。
- 「検出した接続関係」には英語パーツ名、追従に使用した接続、接続点間の距離を表示します。距離は入力モデルの座標単位で、mmなどの物理単位は推定しません。
- 左上の回転矢印「編集を初期化」は全倍率を1.00、全移動量を0に戻します。隣のアイコンはモデル全体が入る位置にカメラを合わせます。
- すべての3D表示はTurntable Rotationです。入力GLB内で指定した上方向（±X/±Y/±Z）を表示の鉛直方向へ回転し、鉛直軸の周りにドラッグで回転します。ホイールでズームできます。入力・分割・編集・結合の表示で同じ回転を使い、画面をひねる回転は行いません。
- 「編集後 GLB」から、変更後の頂点を持つ独立パーツのGLBを保存できます。
- 編集後に「一つのMeshへ結合」を押すと、元の接続情報を使って境界を橋渡しし、面色を残した一つのMeshを下段に表示します。「結合後 GLB」「結合後 NPZ」から保存できます。

## 中心と計算式

承認した方針どおり、中心はパーツを囲む軸に平行な直方体（AABB）の中心です。ボクセル化や頂点の平均は使いません。

```text
center = (元頂点の各軸の最小値 + 元頂点の各軸の最大値) / 2
編集後の頂点 = center + 倍率 × (元頂点 - center)
```

この計算の後、接続への追従がオンなら各パーツに自動の平行移動を加えます。境界なじませを選んだパーツには局所変形を適用し、最後に各パーツ固有のX/Y/Z移動を加えます。なじませ未選択・全体移動の場合は以下の式です。

```text
最終頂点 = center + 倍率 × (元頂点 - center) + 自動追従の移動量 + 手動のX/Y/Z移動量
```

常に元の頂点から計算するので、編集は累積しません。全倍率を1.00、全移動量を0に戻すと元の形状と位置に戻ります。手動移動は倍率で拡大されません。

## 断面基準の移動

`movement_axes.py` が、選択した元の共有境界のエッジを使って平面を近似します。辺長による重み付きの中心・共分散を計算し、共分散の最小固有値に対応する方向を法線Nにします。各辺を一様な線分として積分するため、同じ辺を細かく分割しただけでは近似平面が変わりません。Nの符号は接続先から操作パーツへ向く側を優先します。

表示上の横軸を平面へ投影してUを決め、`V = N × U` として右手系の直交3軸を作ります。境界が点・直線に近い場合は入力XYZへ戻して通知します。非平面性が大きい場合も通知します。

```text
入力座標での手動移動 = U移動量 × U軸ベクトル + V移動量 × V軸ベクトル + N移動量 × N軸ベクトル
```

軸は変形前の境界で決め、倍率や手動移動に応じて再推定しません。パーツ名、元頂点・元面の対応、編集用の入力座標は維持します。UIが送る `offsets` と保存する `manual_translations` は従来どおり入力XYZのベクトルです。移動軸の基準を変えると表示中の3成分を換算し、パーツの位置は保持します。使用した軸と基準接続は `movement_frames` に保存します。

この処理は移動の方向を決めます。頂点への移動量の配分は、次節の移動方法で決まります。

## 断面固定移動

`boundary_motion.py` が、元メッシュのすべての共有境界から、パーツ表面の辺をたどる最短距離を計算します。接続部が複数あれば、その全境界を固定します。「移動軸の基準接続」で選んだ1か所だけを固定する処理ではありません。同じ座標の継ぎ目の頂点にも同じ重みを使います。

```text
d(v) = 共有境界から頂点vまで辺をたどった最短距離
L = 境界へ到達できる頂点のdの最大値
R = 遷移範囲の割合 × L
t = min(d(v) / R, 1)
w(v) = 3t² - 2t³
最終頂点v = 拡大縮小・追従・境界なじませ後の頂点v + w(v) × 手動移動量
```

境界では重み0、遷移帯の中間では0.5、遷移帯より遠い頂点では1です。固定位置は移動操作の直前の境界で、入力時の座標へ引き戻しません。全体移動では全頂点の重みを1にします。既存の隙間や、他のパーツの全体移動は補正しません。
距離は一度計算してキャッシュし、割合・倍率・方向・移動量の変更では再探索しません。割合を変えると重みだけを再計算します。ドラッグ中はThree.jsが同じ重みで頂点を更新し、GPU推論や外部APIは呼びません。

境界へつながらない領域は重み1で動かして通知します。遷移帯に中間頂点がない場合や、全頂点が境界上で動かせない場合も通知します。頂点の追加や細分化は行いません。
この移動は局所変形として自己交差も検査します。色、元頂点・元面の対応、パーツIDを保持してGLB出力と再結合へ渡します。設定と距離統計は `connection_following.boundary_motion` に保存します。移動方法・割合の変更で再結合結果を無効化します。`manual_translations` と `translations` は全強度時の指定移動量で、各頂点の実移動量はその値に重みを掛けたものです。

## Faceの重なり表示

「Faceの重なりを表示」は初期状態でオンです。移動・倍率・自動追従・境界なじませをすべて適用した頂点をPython側で検査し、未編集時にはない交差ペアのFaceだけを編集表示に赤く重ねます。操作中は形状を即時表示し、判定色はスライダーを離した後に更新します。更新前の色は隠して「操作終了後に重なり表示を更新します」と表示します。編集値は拒否せず、ユーザーが移動や倍率をさらに調整できます。

基準は、現在選択中の分割・補正結果を倍率1・移動0で読み込んだ形状です。元から交差しているFaceの組をすべて記録して除外します。比較単位は順序に依存しないFaceの組なので、元から交差していたFaceでも、別のFaceと新しく交差すれば表示します。同じ組の交差量の増減は比較しません。表示をオフにしたまま編集してからオンにしても、基準は未編集形状のままです。モデルや分割・補正結果が変わると基準も更新し、編集を初期化すると新しい交差の表示は消えます。

接続への追従は、元の接続点からの変位同士を比較して計算します。境界なじませも元頂点に変位を加える式を使い、倍率1・移動0で元の座標を正確に保持します。未編集なのに、絶対座標の引き算による丸め誤差が交差判定の閾値をまたぐことを防ぎます。Pythonの計算とブラウザの追従計算に同じ定義を使います。

`mesh_overlaps.py` が三角形のAABBからBVHを作って候補を絞り、三角形同士の交差を判定します。同一平面にある三角形の面積を持つ重複も検出します。通常の共有辺・共有頂点だけの接触は重複に数えません。未編集モデルの中心・最大寸法を基準座標 `frame` として保持し、編集後と結合後にも同じ座標で正規化します。長さの許容誤差も未編集モデルの最大寸法の `1e-9` に固定します。別パーツの移動で全体の範囲が変わっても、静止した面同士の判定条件は変わりません。元の頂点・面は変更しません。

正の一様倍率・平行移動だけでは、同じパーツ内部に新しい自己交差は生じません。境界なじませと移動をすべて適用した頂点を一様変換の座標と比較し、変化しなかったパーツ内の組は新規交差から除外します。パーツ間の交差は引き続き検査します。境界なじませや断面固定移動で局所変形したパーツは、内部の自己交差も検査します。

同じ形状の検査結果と未編集時の基準はキャッシュします。局所的な編集を見落とさないよう、頂点と面の全バイト・基準座標からキャッシュ識別子を作ります。結果は `st.session_state["part_editing"]["overlap_report"]` に保持し、新しい面ID・交差組数・全交差ペアを参照できます。`total_pair_count` は除外前、`ignored_pair_count` は除外した組数です。内訳は `ignored_reference_pair_count`（未編集時の交差）、`ignored_uniform_pair_count`（一様変換だけのパーツ内）です。面IDは、編集パーツの順に面を連結した配列に対するIDです。比較には最大100組の `sample_pairs` ではなく、全交差ペアの `pairs` を使います。

「一つのMeshへ結合」の後も同じ基準と比較します。結合で面順序が変わるため、元Faceの対応情報で未編集時の交差ペアを除外します。一様変換だけのパーツでも、結合時の頂点統合で座標が変わった元Faceは再検査します。追加した橋渡し面・接点の補助面は未編集時にはない面なので、それらとの交差も新しい交差として結合プレビューに表示します。この結果は `st.session_state["part_editing"]["rejoined"]["overlap_report"]` に保持します。赤色は確認用の表示だけに適用し、編集後・結合後のGLB/NPZには元のパーツ色を保存します。

現在表示している形状の表面交差を検査するもので、移動途中の連続衝突判定や内部体積の包含判定は行いません。交差がなくても、開いた境界や非多様体などが残る場合があり、水密なメッシュであることとは別に確認が必要です。Faceの削除・自動修復は行いません。

## 境界付近のなじませ

元メッシュで共有していた境界頂点の対応を使い、選択したパーツの境界を接続先の現在の形状に合わせます。接続先が倍率1・移動0なら、その境界は元の位置に残ります。自動追従で接続先が動く場合は、その位置に合わせます。

1. 変形前の各パーツで、共有境界から各頂点までの最短距離 `d` を、メッシュの辺の長さを足して求めます。空間で近いだけの別の面へ飛び移りません。座標が完全一致する頂点コピーは、距離の計算時だけ同じ頂点として扱います。
2. 境界へ到達できる頂点のうち、最も遠い距離を `L` とします。初期のなじませ幅は `R = 0.20 × L` です。複数の境界がある場合は、最寄りの境界までの距離の最大値を使います。幅は元形状から計算するため、倍率操作で変わりません。
3. `t = min(d/R, 1)` とし、境界側の重みを `w = 1 - (3t² - 2t³)` とします。境界では接続先の形状100%、幅の外では自身の指定倍率100%です。間では滑らかに混ぜます。

```text
T_p(v) = パーツp自身の中心基準スケーリング + 自動追従
T_r(v) = 同じ元頂点vに、接続先rの中心基準スケーリングと自動追従を適用した位置
最終頂点 = T_p(v) + Σ_r 重み_r(v) × (T_r(v) - T_p(v)) + パーツpの手動XYZ移動
```

共有境界の接続先には、なじませ未選択のパーツを優先します。複数あれば基準パーツ、次にID順です。両側を選択したときも同じ基準を使うため、処理順に依存して境界がずれることを避けます。複数の接続先に挟まれたパーツでは、各境界までの距離を使って影響を滑らかに混ぜます。未選択パーツ同士が接する点で位置が食い違う場合は通知します。

手動XYZ移動はなじませの後に加えます。境界を保持する場合は断面固定移動を選びます。面・頂点の追加や削除は行わず、パーツID、元頂点対応、面の色分けを維持します。境界へつながらない独立領域は従来の拡大縮小を使います。遷移帯に中間頂点がない場合は通知します。範囲を広げるか、入力メッシュの細分化が必要です。

境界の位置を一致させる処理なので、接続部の法線・曲率の完全な一致、面の交差回避、水密化を保証するものではありません。

## 接続の検出と追従

`connections.py` が、NPZの全体頂点・面・各面の所属を使って接続を検出します。

1. 座標が完全一致する頂点を、境界検出のときだけ同じ頂点とみなします。UVや法線の都合で複製された頂点にも対応します。編集用の頂点配列は結合しません。
2. 2面が共有するエッジで、面のパーツIDが異なるものを接続境界とします。点だけの接触、微小な隙間、近いだけの別メッシュには接続を作りません。3面以上が共有する異種パーツ間エッジは曖昧なため除外して通知します。
3. パーツの組ごとに、境界エッジの連結成分を分けます。離れた接続領域を一つの中心へまとめません。
4. 各領域で、エッジ中点を長さで重み付けした平均を接続点にします。細かく分割された頂点が多い場所へ偏るのを避けます。
5. 境界長の長い接続から優先して、循環しない接続グラフを作ります。選択した基準パーツから親→子の順に位置を計算します。

```text
親側の接続点 = 親の元中心 + 親倍率 × (元接続点 - 親の元中心) + 親の移動量
子側の仮接続点 = 子の元中心 + 子倍率 × (元接続点 - 子の元中心)
子の移動量 = 親側の接続点 - 子側の仮接続点
```

子自身もスケーリングされている場合を含め、両側の接続点を合わせます。子の移動を孫にも伝えます。
基準パーツにつながらないグループは、それぞれID最小の非空パーツを自動追従の基準にします。空パーツは接続先にも基準にも使わず、移動スライダーも無効にします。

輪状の接続や同じ組の複数接続がある場合、平行移動だけで全条件を満たせないことがあります。優先した接続以外を無視したまま成功扱いにせず、通知と表・点の表示で残りのずれを確認できるようにしています。全接続を同時に最適化する機能はありません。
境界検出は幾何的な隣接を使うため、セグメントの誤った飛び地による境界も候補になります。接続点の自動判定が意図どおりか、表示で確認してください。

## ブラウザ表示とPythonの対応

名前推定時の自動姿勢合わせがオンなら、処理用GLBを＋Z・Z＝0へ変換した後に分割します。入力プレビューは保存した変換行列を適用し、分割・編集・結合は処理用座標を直接使います。この場合、以下の「入力座標」は処理用GLBの座標を指し、表示用の上方向は `+Z` です。元GLBと逆変換は別に保存します。[更新・使用手順](../ip-object-name/AUTO_ORIENTATION.md)を参照してください。

`orientation.json` はInstruct-Particulateの `up_dir_rotation_matrix_to_z()` と同じ6方向の回転を定義します。PythonのPlotly表示とThree.jsの編集表示でこのファイルを共有し、選択した入力軸を表示の+Zへ向けます。Plotlyの軸ラベルには対応する入力軸を表示します。例えば+Yを上に選ぶと、縦軸は「Y（上）」、残りは「X」「-Z」です。

編集表示ではパーツと接続点を同じ表示用グループで回転し、床とTurntableの回転軸は表示の+Zにそろえます。元GLB、編集用頂点、倍率・XYZ移動、GLB/NPZ出力は入力座標のままです。表示の回転を出力へ二重適用しません。方向変更時は視点を初期化し、同じ方向での編集操作中は視点を保持します。

上方向は表示だけの設定ではありません。WSL側は選択方向でVLM用画像をレンダリングし、セグメント前には同じ方向から+Zへ回転します。分割結果の頂点は元の入力座標へ戻して出力します。パーツ生成LLMには物体名と要求文を渡すため、方向の影響は名前推定を介した間接的なものです。入力画面で方向を変えた場合、以前の名前・パーツ構成・分割結果を無効化し、「パーツ構成を作成」からの再実行が必要です。

1. Pythonの `editing.py` がNPZからパーツごとの頂点・面と中心を読み込みます。
2. Pythonの `boundary_blending.py` が選択パーツの境界距離と重みを事前計算し、結果をキャッシュします。スライダーのドラッグ中はThree.jsが同じ中心・倍率・接続グラフ・重みで局所変形まで描画します。毎フレームのPython実行やGLBの再生成は不要です。
3. ドラッグを離すと倍率と移動量をStreamlitへ渡します。Pythonは `follow_connections()`（追従オフなら `scale_parts()`）、`apply_boundary_blend()`、`apply_boundary_motion()` の順に適用します。JavaScript側とPython側の頂点座標の一致を自動テストで確認しています。
4. Pythonで計算したパーツは `st.session_state["part_editing"]["edited_parts"]` に保持します。今後の形状編集処理から利用できます。
5. 接続の情報・基準パーツ・移動量・接続点のずれは `st.session_state["part_editing"]["connections"]` に保持します。「編集後 GLB」には位置補正済みの頂点と、この情報をシーンのメタデータに保存します。接続点の丸印や補助線はGLBの形状へ追加しません。
6. 手動移動は `st.session_state["part_editing"]["offsets"]` に保持します。接続メタデータの `automatic_translations` が自動追従、`manual_translations` が手動移動、`translations` が合計です。GLBの最終頂点と再結合にも手動移動を反映します。
7. なじませの選択ID・割合・距離統計は接続メタデータの `boundary_blending` に保存します。なじませ中の接続点は実際の変形後の境界頂点から計算し、表示の点と診断表の両方へ反映します。

編集元はモデルID・パーツ構成ID・分割ID・NPZ内容で識別します。別の分割結果やCCS補正結果へ切り替えると倍率と移動量を初期化します。
モデル・要求文・向きなどの変更で分割結果が無効になると編集状態も破棄します。ページを再読み込みした場合も倍率は永続保存されません。

入力GLB、分割済みGLB、NPZを上書きしません。元データは保持され、編集済みモデルはダウンロードしたGLBへ保存されます。
なじませ未選択では、接続点が一致しても倍率の異なる境界の幅や形状は一致しない場合があります。干渉回避、切断面の穴埋め・水密化は行わないため、編集内容によって隙間や重なりが生じることがあります。

## ボタンによるメッシュの再結合

スケーリング・位置追従・境界なじませ・X/Y/Zの手動移動を適用した後の形状を使います。結合はボタンを押した時点の結果として保持し、スライダー・基準パーツ・追従設定・なじませ設定を変えたときは古い結合結果を非表示にします。結合ボタンをもう一度押して更新してください。接続点の表示切り替えでは結合結果を保持します。

`rejoining.py` が以下の処理を行います。

1. NPZの `source_vertex_indices` と `source_face_indices` で、各パーツの頂点・面を元モデルへ対応づけます。対応情報が欠ける場合はボタンを無効にします。
2. 元の頂点位置が同じだったコピーについて、編集後も位置が一致するものを統合します。数値誤差としてモデル全体の対角長の `1e-10` を許容します。元の対応が異なる近接頂点を距離だけで結合しません。
3. 元は辺を共有していた異なるパーツの間で、境界が離れた部分に三角形を追加します。位置追従のために選択した接続グラフだけでなく、元の共有境界全体を使います。UVや法線用に座標が完全一致した元頂点は、既存の接続検出と同様に同じ位置として扱います。
4. 接続帯の両側に既存面と逆向きの辺を作り、面の向きをそろえます。3パーツ以上の接点に生じた、同じ元頂点由来の小さな閉じた境界には接続面を追加します。
5. 元の面は順序・位置・パーツ色を維持します。追加した接続帯の2三角形には、隣接する両側の色を1枚ずつ割り当てます。接点の補助面も隣接パーツの色を継承します。

確認用の処理です。面の交差や重なりは修正しません。一般的な穴埋め、元形状の開口部の閉鎖、ブーリアン和は行いません。3面以上が共有する曖昧な元境界には橋渡し面を自動生成しません。頂点の統合で不要になる接続面や面積ゼロの接続面は追加しません。

「Mesh数：1」は一つの頂点・面配列にまとめたことを表します。元から離れたメッシュ間に新しい接続は作らないため、連結成分が複数残ることがあります。画面に成分数と元面・接続面の数を表示します。水密化や3Dプリントへの適合を保証する処理ではありません。

- **結合後GLB**：glTF上のMesh一つ・ノード一つとして保存します。同じ頂点座標の配列を使い、パーツ色ごとに面をマテリアルのグループへ分けます。面色を頂点で平均して混ぜる処理は行いません。読み込みソフトによっては、このグループを別々の形状として扱う場合があります。
- **結合後NPZ**：統合済みの `vertices`、`faces`、面ごとの `face_part_ids`、`face_colors`、`source_face_indices`、`is_bridge` を保存します。追加面の `source_face_indices` は `-1`、`is_bridge` は `True` です。Pythonで結合した頂点の共有関係をそのまま読み込めます。

元の入力・分割ファイルと、編集中の独立パーツは上書きしません。GLBとNPZは画面からダウンロードしたファイルへ保存されます。

## 起動と変更箇所

通常のStreamlit起動方法は[README.md](README.md)と同じです。起動中なら画面を再読み込みしてください。
既存のPython依存だけで動きます。WSL側のファイル更新、Node.jsのインストール、フロントエンドの再ビルドは通常の起動に不要です。

`scale_component/dist/` にビルド済みJavaScriptとHTMLを同梱しています。ブラウザUIのソースを変更するときだけ、Node.jsとpnpmで再ビルドします。

```powershell
cd scale_component
pnpm install --frozen-lockfile --store-dir node_modules/.pnpm-store --node-linker hoisted --package-import-method copy
node build.mjs
node --test tests/connection_solver.test.mjs
node --test tests/editor_args.test.mjs
node --test tests/turntable_controls.test.mjs
node --test tests/boundary_blending.test.mjs
node --test tests/orientation.test.mjs
node --test tests/translation_frames.test.mjs
node --test tests/overlap_highlights.test.mjs
```

`src/editor.js` が動作、`dist/index.html` がレイアウト、`build.mjs` がJavaScriptと第三者ライセンス一覧の生成を担当します。
依存はロックファイルで固定しています。Three.js（MIT）、Streamlit Component Library（Apache-2.0）、Lucide（ISC）のライセンスと依存ライブラリの通知を `dist/THIRD_PARTY_LICENSES.txt` に同梱しています。

更新前のWindows UIが移動量や範囲を送らない場合も、旧データの表示は継続できます。その場合、移動スライダーを無効にしてUI再起動の案内を表示します。Windows側のStreamlitを停止・再起動してから、ブラウザを再読み込みしてください。WSL側の再起動や変更は不要です。

JavaScriptはビルド内容のハッシュを付けたURLで配信し、Python側のコンポーネント名にも同じハッシュを使用します。ビルド後にWindows UIを再起動すると、新しいコードを読み込みます。

参照：[Three.js OrbitControls](https://threejs.org/docs/#examples/en/controls/OrbitControls)、[Streamlit components](https://docs.streamlit.io/develop/concepts/custom-components/intro)。
