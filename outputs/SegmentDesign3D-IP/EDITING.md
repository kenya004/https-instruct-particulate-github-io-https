# パーツの形状・位置編集

分割結果、または現在選択しているCCS補正結果の各パーツを、個別に拡大・縮小します。倍率を変更したパーツから接続先へ、接続面の法線方向の変位を伝える平行移動も適用します。
各パーツを3方向に移動できます。初期基準は接続断面の近似平面で、平面内のU/Vと法線Nを使います。入力X/Y/Zへも切り替えられます。全体移動は接続位置を自由にずらし、なじませる移動は編集パーツ自身の移動量を境界で0にして、遠い頂点ほど指定量へ近づけます。
編集用の入力はAPIから取得済みの `parts.npz` と対応表です。編集の操作でGPU推論やGeminiを呼び直しません。

## 接続方式の自動設定

新しいパーツ構成では、既存のテキストLLMが同じ応答で推定した`editing_policy`を使います。「LLMによる接続方針・変更」で接続ごとの方式を変更できます。なじませは編集したパーツに適用し、閉鎖・延長では推定された本体・基準側・変形側を使います。閉鎖・延長の基準側は接続ペアごとに変更できます。幾何学的な形状分類は追加していません。

| 方式 | 編集時と結合時の処理 |
|---|---|
| なじませ | 編集したパーツ自身の倍率・移動量を初期60%の遷移帯で調整する。各パーツの編集を合成し、すべてこの方式なら「なじませて一体化」で対応頂点を統合する |
| 閉鎖して再結合 | ①蓋を作る → ②自由に編集・移動 → ③変形側から基準側へ延長 → ④Boolean結合 |
| 両方式の混在 | なじませる境界は一致を保ち、閉鎖再結合する接続だけを延長する。内部の共通の蓋は④で取り除く |

なじませには固定の基準側を設けません。Cupを編集すればCupに、Handleを編集すればHandleになじませます。追従で動いただけのパーツは、その自動移動を保持します。両方を編集したときは各パーツ自身の編集への補正を合成し、最後に操作したパーツによる切り替えや変位の累積を行いません。同じペアの複数断面には同じ接続方式を適用します。

共有境界がない推定関係には警告を出し、存在しない接続は作成しません。推定結果がない古いプランは従来の手動設定を残します。以下の「なじませを適用するパーツ」「パーツごとの移動方法」の手動選択は、この旧プラン向けです。

GLB・NPZにはパーツの色・元面の対応と使用した接続方針を保存します。印刷用STLは水密性・面向き・退化面・交差・連結性の検査を通過した結果だけ出力します。実際の肉厚や造形条件の判定は含みません。

## 操作

「パーツ編集」に、パーツ数に合わせたスライダーと3D表示が現れます。パーツを選択してからスライダーを出す操作は不要です。数が多いときはスライダーの一覧をスクロールできます。

- ラベルはLLMが作成してInstruct-Particulateに渡した英語の `name` です。
- 各倍率の初期値は1.000、表示範囲は0.500～1.500、刻みは0.001です。XYZを同じ倍率で変えます。以前の編集値が範囲外なら、そのパーツの表示範囲を広げて値を保持します。
- 同名パーツがあっても、対応は `part_id` で保持します。
- 面が割り当てられなかったパーツも一覧に残り、「面なし」と表示してスライダーを無効にします。
- 「移動方向の基準」の初期値は「断面の近似平面」です。「断面U 移動」「断面V 移動」「法線N 移動」で、そのパーツの移動量を指定します。3方向とも初期値0です。断面がないパーツは入力XYZを使い、全パーツを入力XYZへ切り替えることもできます。入力モデルの座標単位を使い、mmなどの単位は推定しません。
- 「パーツごとの移動方法」を開くと、英語パーツ名ごとに全体移動・断面固定移動を選べます。初期値は全体移動です。固定移動の遷移範囲はパーツごとに初期60%、範囲1～100%です。断面や面がないパーツでは選択できません。設定変更時は現在の移動量を新しい重みで再適用します。
- 「移動軸を表示」で、赤U・緑V・青Nの矢印を表示します。入力XYZの場合は同じ色順でXYZです。複数の接続があるパーツでは「移動軸の基準接続」から選びます。初期値は境界が最も長い接続で、同長なら接続ID順です。
- 移動範囲は元モデル全体の最大寸法をRとして各軸 `-0.2R～+0.2R`、刻みは `R/5000` です。以前の移動量や軸の変更で値が範囲を超えた場合、その値を保持できるまで表示範囲を広げます。軸の切り替え自体では形状・位置を変更しません。
- 3方向の移動スライダーは、マウス・タッチで0付近へ動かすと0へ吸着します。吸着中は緑色になり、さらにドラッグすると反対側へ抜けられます。矢印キーでは吸着を使わず、一目盛りずつ微調整できます。全体移動・断面固定移動、入力XYZ・断面U/V/Nのどちらにも適用します。
- 固定した「追従の基準パーツ」は選びません。どのパーツの倍率を変更しても、つながる別パーツへ変位を伝えます。LLMの本体・基準側の情報は閉鎖・延長の役割に使用します。旧プランでは詳細設定の「閉鎖・延長の本体（手動構成）」からその役割を選べます。
- 「編集したパーツから接続先へ追従」は初期状態でオンです。接続面の法線方向の成分だけを伝え、対象パーツ自身の倍率による自己平行移動は加えません。複数のパーツの倍率を変更した場合は、それぞれが他パーツへ与える変位を合成します。オフにすると自動移動を0にします。
- 全体移動では、追従がオンでも手動移動時の接続点を維持しません。断面固定移動では移動直前の共有境界を保持します。どちらも親パーツの手動移動を子へ加えません。実際の境界位置は接続点と診断表に反映します。
- 「接続点を表示」で丸印を切り替えられます。緑は両側の点が一致した状態、橙とその間の線はずれがある状態です。
- 「境界なじませを適用するパーツ」で、境界付近の拡大縮小を調整するパーツを複数選べます。初期状態は未選択です。「境界なじませの範囲（%）」は初期値60%、範囲1～100%です。幅の基準は、元のパーツを囲む軸に平行なBox（AABB）の最長辺です。同じパーツの各断面に共通の幅を使います。
- 「検出した接続関係」には英語パーツ名、追従に使用した接続、接続点間の距離を表示します。共通基準面にまとめた接続ID・法線・法線方向の残差も表示します。丸印の中心位置は拘束していないため、橙色でも方向追従の失敗とは限りません。距離は入力モデルの座標単位です。
- 左上の回転矢印「編集を初期化」は全倍率を1.00、全移動量を0に戻します。隣のアイコンはモデル全体が入る位置にカメラを合わせます。
- すべての3D表示はTurntable Rotationです。入力GLB内で指定した上方向（±X/±Y/±Z）を表示の鉛直方向へ回転し、鉛直軸の周りにドラッグで回転します。ホイールでズームできます。入力・分割・編集・結合の表示で同じ回転を使い、画面をひねる回転は行いません。
- 「編集後 GLB」から、変更後の頂点を持つ独立パーツのGLBを保存できます。
- 「断面を閉じる」で、現在の独立パーツに分割由来の断面の蓋を生成できます。下のプレビューと診断を確認し、「蓋付き GLB」「蓋付き NPZ」で保存します。詳細は[分割断面を閉じる](#分割断面を閉じる)を参照してください。
- 編集後に「一つのMeshへ結合」を押すと、元の接続情報を使って境界を橋渡しし、面色を残した一つのMeshを下段に表示します。「結合後 GLB」「結合後 NPZ」から保存できます。

## 中心と計算式

承認した方針どおり、中心はパーツを囲む軸に平行な直方体（AABB）の中心です。ボクセル化や頂点の平均は使いません。

```text
center = (元頂点の各軸の最小値 + 元頂点の各軸の最大値) / 2
編集後の頂点 = center + 倍率 × (元頂点 - center)
```

この計算の後、接続への追従がオンなら各パーツに自動の平行移動を加えます。境界なじませを選んだパーツには局所変形を適用し、最後に各パーツ固有のX/Y/Z移動を加えます。なじませ未選択・全体移動の場合は以下の式です。

```text
最終頂点 = center + 倍率 × (元頂点 - center) + 自動追従の移動量 + 手動のX/Y/Z移動量
```

常に元の頂点から計算するので、編集は累積しません。全倍率を1.00、全移動量を0に戻すと元の形状と位置に戻ります。手動移動は倍率で拡大されません。

## 断面基準の移動

`movement_axes.py` が、選択した元の共有境界のエッジを使って平面を近似します。辺長による重み付きの中心・共分散を計算し、共分散の最小固有値に対応する方向を法線Nにします。各辺を一様な線分として積分するため、同じ辺を細かく分割しただけでは近似平面が変わりません。Nの符号は接続先から操作パーツへ向く側を優先します。

表示上の横軸を平面へ投影してUを決め、`V = N × U` として右手系の直交3軸を作ります。境界が点・直線に近い場合は入力XYZへ戻して通知します。非平面性が大きい場合も通知します。

```text
入力座標での手動移動 = U移動量 × U軸ベクトル + V移動量 × V軸ベクトル + N移動量 × N軸ベクトル
```

軸は変形前の境界で決め、倍率や手動移動に応じて再推定しません。パーツ名、元頂点・元面の対応、編集用の入力座標は維持します。UIが送る `offsets` と保存する `manual_translations` は従来どおり入力XYZのベクトルです。移動軸の基準を変えると表示中の3成分を換算し、パーツの位置は保持します。使用した軸と基準接続は `movement_frames` に保存します。

この処理は移動の方向を決めます。頂点への移動量の配分は、次節の移動方法で決まります。

## 断面固定移動

`boundary_motion.py` が、編集前の接続先パーツの三角形表面までの最短距離を使います。接続部が複数あれば、その全境界を固定します。「移動軸の基準接続」で選んだ1か所だけを固定する処理ではありません。同じ座標の継ぎ目の頂点にも同じ重みを使います。

```text
d(v) = 接続先パーツの三角形表面から頂点vまでの最短距離（実際の断面頂点は0に固定）
L = 元のパーツを囲むAABBの最長辺
R = 遷移範囲の割合 × L
t = min(d(v) / R, 1)
w(v) = 3t² - 2t³
最終頂点v = 拡大縮小・追従・境界なじませ後の頂点v + w(v) × 手動移動量
```

境界では重み0、遷移帯の中間では0.5、遷移帯より遠い頂点では1です。固定位置は移動操作の直前の境界で、入力時の座標へ引き戻しません。全体移動では全頂点の重みを1にします。既存の隙間や、他のパーツの全体移動は補正しません。
初期値は`R = 0.60 × L`です。複数の断面にも同じ幅を使い、同じ本体につながる取っ手では、その本体表面までの距離で重みを計算します。断面の数を変えても`L`は変わりません。全頂点が遷移帯内に入る形状では、最も遠い頂点も指定移動量の一部が適用される状態になります。
距離は一度計算してキャッシュし、割合・倍率・方向・移動量の変更では再探索しません。割合を変えると重みだけを再計算します。ドラッグ中はThree.jsが同じ重みで頂点を更新し、GPU推論や外部APIは呼びません。

境界へつながらない領域は重み1で動かして通知します。遷移帯に中間頂点がない場合や、全頂点が境界上で動かせない場合も通知します。頂点の追加や細分化は行いません。
この移動は局所変形として自己交差も検査します。色、元頂点・元面の対応、パーツIDを保持してGLB出力と再結合へ渡します。設定と距離統計は `connection_following.boundary_motion` に保存します。移動方法・割合の変更で再結合結果を無効化します。`manual_translations` と `translations` は全強度時の指定移動量で、各頂点の実移動量はその値に重みを掛けたものです。

## Faceの重なり表示

「Faceの重なりを表示」は初期状態でオンです。移動・倍率・自動追従・境界なじませをすべて適用した頂点をPython側で検査し、未編集時にはない交差ペアのFaceだけを編集表示に赤く重ねます。操作中は形状を即時表示し、判定色はスライダーを離した後に更新します。更新前の色は隠して「操作終了後に重なり表示を更新します」と表示します。編集値は拒否せず、ユーザーが移動や倍率をさらに調整できます。

基準は、現在選択中の分割・補正結果を倍率1・移動0で読み込んだ形状です。元から交差しているFaceの組をすべて記録して除外します。比較単位は順序に依存しないFaceの組なので、元から交差していたFaceでも、別のFaceと新しく交差すれば表示します。同じ組の交差量の増減は比較しません。表示をオフにしたまま編集してからオンにしても、基準は未編集形状のままです。モデルや分割・補正結果が変わると基準も更新し、編集を初期化すると新しい交差の表示は消えます。

接続への追従は、基準側の元の接続面からの変位を法線方向へ投影して計算します。境界なじませも元頂点に変位を加える式を使い、倍率1・移動0で元の座標を正確に保持します。Pythonの計算とブラウザの追従計算に同じ定義を使います。

`mesh_overlaps.py` が三角形のAABBからBVHを作って候補を絞り、三角形同士の交差を判定します。同一平面にある三角形の面積を持つ重複も検出します。通常の共有辺・共有頂点だけの接触は重複に数えません。未編集モデルの中心・最大寸法を基準座標 `frame` として保持し、編集後と結合後にも同じ座標で正規化します。長さの許容誤差も未編集モデルの最大寸法の `1e-9` に固定します。別パーツの移動で全体の範囲が変わっても、静止した面同士の判定条件は変わりません。元の頂点・面は変更しません。

正の一様倍率・平行移動だけでは、同じパーツ内部に新しい自己交差は生じません。境界なじませと移動をすべて適用した頂点を一様変換の座標と比較し、変化しなかったパーツ内の組は新規交差から除外します。パーツ間の交差は引き続き検査します。境界なじませや断面固定移動で局所変形したパーツは、内部の自己交差も検査します。

同じ形状の検査結果と未編集時の基準はキャッシュします。局所的な編集を見落とさないよう、頂点と面の全バイト・基準座標からキャッシュ識別子を作ります。結果は `st.session_state["part_editing"]["overlap_report"]` に保持し、新しい面ID・交差組数・全交差ペアを参照できます。`total_pair_count` は除外前、`ignored_pair_count` は除外した組数です。内訳は `ignored_reference_pair_count`（未編集時の交差）、`ignored_uniform_pair_count`（一様変換だけのパーツ内）です。面IDは、編集パーツの順に面を連結した配列に対するIDです。比較には最大100組の `sample_pairs` ではなく、全交差ペアの `pairs` を使います。

「一つのMeshへ結合」の後も同じ基準と比較します。結合で面順序が変わるため、元Faceの対応情報で未編集時の交差ペアを除外します。一様変換だけのパーツでも、結合時の頂点統合で座標が変わった元Faceは再検査します。追加した橋渡し面・接点の補助面は未編集時にはない面なので、それらとの交差も新しい交差として結合プレビューに表示します。この結果は `st.session_state["part_editing"]["rejoined"]["overlap_report"]` に保持します。赤色は確認用の表示だけに適用し、編集後・結合後のGLB/NPZには元のパーツ色を保存します。

現在表示している形状の表面交差を検査するもので、移動途中の連続衝突判定や内部体積の包含判定は行いません。交差がなくても、開いた境界や非多様体などが残る場合があり、水密なメッシュであることとは別に確認が必要です。Faceの削除・自動修復は行いません。

## 境界付近のなじませ

元メッシュの共有境界と編集前の距離場を使い、各パーツ自身の編集量だけを補正します。なじませ方式の接続では両側を編集候補とし、倍率が1のパーツには倍率のなじませ変形を加えません。編集元の倍率変更で接続先が追従した場合は、その追従先へ編集元の境界を合わせます。

1. 編集前の各頂点から、接続先パーツの三角形表面までの最短距離 `d` を求めます。頂点間の距離ではなく、三角形内部・辺も含む表面への距離です。元の共有境界頂点は距離0とし、同じ座標の頂点コピーにも同じ重みを使います。
2. 元のパーツを囲むAABBの最長辺を `L` とします。初期のなじませ幅は `R = 0.60 × L` です。同じ本体につながる上下の断面には、本体までの距離に対して共通の幅を使います。断面数によって幅は縮まず、倍率・移動操作でも変わりません。範囲が広く全頂点が遷移帯内に入る場合は、内部にもなじませが残ります。
3. `t = min(d/R, 1)` とし、境界側の重みを `w = 1 - (3t² - 2t³)` とします。境界では自身の倍率変化を接続先へ伝わる追従量へ置き換え、幅の外では自身の指定倍率100%です。間では滑らかに混ぜます。

```text
K_rp = パーツpの単位倍率変化が接続先rへ伝える移動量（追従オフなら0）
基本頂点 = v + (s_p - 1)(v - c_p) + 自動追従の移動量_p
倍率の補正 = (s_p - 1) Σ_r w_pr(v) [K_rp - (v - c_p)]
最終頂点 = 基本頂点 + 倍率の補正 + (1 - Σ_r w_pr(v)) × 手動移動量_p
```

別パーツの倍率変化による自動追従は、基本頂点に含めたまま保持します。自身の倍率変化に対する補正だけを加えるため、両側を順に編集しても、それぞれの編集が合成されます。全倍率1・移動0に戻すと元の座標へ戻ります。接続先が複数の別パーツの場合は、各表面までの距離による影響を元の接続境界への辺経路距離で配分・正規化します。同じ本体への複数接続では減衰の距離に辺経路距離を使いません。同じ境界頂点に複数の接続先がある場合はID順で相手を選び、警告します。

表面距離は空間インデックスを使い、小分けに計算して一時メモリを抑えます。元形状・対象パーツ・接続が同じならキャッシュを再利用し、範囲・倍率・移動量だけの変更では表面を再探索しません。自動接続方針のなじませ移動には倍率と同じ重みを渡し、自身の移動量だけを境界で0へ減衰させます。GLBの頂点とブラウザ表示も同じ重みで計算します。メタデータの方式は`edited_part_surface_blend_v4`、`application`は`edited_part`です。

接続先の表面は、分割結果にある面をそのまま距離の対象にします。距離計算のために断面を閉鎖したり、穴を補完したりはしません。拡大縮小の中心は従来のパーツAABB中心で、完全な半円・相似形を拘束する機能は追加していません。

手動XYZ移動はなじませの後に加えます。境界を保持する場合は断面固定移動を選びます。面・頂点の追加や削除は行わず、パーツID、元頂点対応、面の色分けを維持します。境界へつながらない独立領域は従来の拡大縮小を使います。遷移帯に中間頂点がない場合は通知します。範囲を広げるか、入力メッシュの細分化が必要です。

境界の位置を一致させる処理なので、接続部の法線・曲率の完全な一致、面の交差回避、水密化を保証するものではありません。

## 接続の検出と追従

`connections.py` が、NPZの全体頂点・面・各面の所属を使って接続を検出します。

1. 座標が完全一致する頂点を、境界検出のときだけ同じ頂点とみなします。UVや法線の都合で複製された頂点にも対応します。編集用の頂点配列は結合しません。
2. 2面が共有するエッジで、面のパーツIDが異なるものを接続境界とします。点だけの接触、微小な隙間、近いだけの別メッシュには接続を作りません。3面以上が共有する異種パーツ間エッジは曖昧なため除外して通知します。
3. パーツの組ごとに、境界エッジの連結成分を分けます。物理的な断面のIDは個別に保持します。
4. 各領域で、エッジ中点を長さで重み付けした平均を接続点にします。細かく分割された頂点が多い場所へ偏るのを避けます。
5. LLMの付属関係、次に境界長を優先して、循環しないパーツ間の接続グラフを作ります。同じパーツの組に属する複数断面は、すべてその組の接続面の候補に含めます。追従方向は一つの本体に固定せず、各パーツを変位の発生元とした応答をあらかじめ求めます。
6. `connection_planes.py`で各断面を平面近似します。同じ相手への断面のうち、法線の向きが15度以内のものをまとめます。共通の中心・法線は断面ごとの平均で、周長や頂点密度が大きい断面へ偏らせません。法線の向きが異なる面や、表裏が反対の面は別グループです。AABB中心は法線の符号を決める補助に使います。

共通接続面が一つの接続では、変位を受け渡す方向へ投影します。この計算を各パーツを発生元として行い、応答係数を保存します。

```text
C = 共通接続面の元の中心
N = 共通接続面の単位法線
伝わる変位 = N × dot(N, 接続元の変形による変位)
K[j←i] = パーツiの倍率を1から2にしたとき、パーツjへ伝わる変位
K[i←i] = 0
パーツjの自動移動 = Σ(i≠j) (パーツiの倍率 - 1) × K[j←i]
```

Cupを拡大するとCup自身の位置を変えずにHandleへ、Handleを拡大するとHandle自身の位置を変えずにCupへ、その倍率変更の影響を伝えます。既に別パーツを編集していた場合、そのパーツから受けている移動量は保持します。スライダーを触る順番によって起点を切り替える処理ではないため、選択を変えた瞬間にモデルが戻ることはありません。全倍率を1に戻すと自動移動も0に戻ります。

面に沿った移動や断面間隔の変化は、この平行移動で一致させません。必要な境界の変形はなじませ・延長・再結合で扱います。手動移動はこの倍率による伝搬の後に適用し、他パーツ全体へ自動伝搬しません。

同じ組に異なる方向の面がある場合は、各面の法線方向の条件をまとめ、最小二乗・最小ノルムの一つの平行移動を計算します。両側を挟む面など、同時に満たせない条件には残差を表示します。共通面・応答行列は元形状から決め、スライダー操作中はブラウザでも同じ係数を使います。回転は自動適用しません。
離れたグループ間には変位を伝えません。空パーツは変位の発生元・接続先に使わず、移動スライダーも無効にします。

輪状のパーツ間接続は、追従の木に含まれない組を通知します。点・直線に近い断面で平面を決められない場合は、その領域の方向追従を保留して通知します。非平面の断面では近似した方向を使う旨を表示します。接続中心の一致や、全パーツの衝突回避を拘束する機能ではありません。Faceの交差表示で別途確認してください。
境界検出は幾何的な隣接を使うため、セグメントの誤った飛び地による境界も候補になります。接続点の自動判定が意図どおりか、表示で確認してください。

## ブラウザ表示とPythonの対応

名前推定時の自動姿勢合わせがオンなら、処理用GLBを＋Z・Z＝0へ変換した後に分割します。入力プレビューは保存した変換行列を適用し、分割・編集・結合は処理用座標を直接使います。この場合、以下の「入力座標」は処理用GLBの座標を指し、表示用の上方向は `+Z` です。元GLBと逆変換は別に保存します。[更新・使用手順](../ip-object-name/AUTO_ORIENTATION.md)を参照してください。

`orientation.json` はInstruct-Particulateの `up_dir_rotation_matrix_to_z()` と同じ6方向の回転を定義します。PythonのPlotly表示とThree.jsの編集表示でこのファイルを共有し、選択した入力軸を表示の+Zへ向けます。Plotlyの軸ラベルには対応する入力軸を表示します。例えば+Yを上に選ぶと、縦軸は「Y（上）」、残りは「X」「-Z」です。

編集表示ではパーツと接続点を同じ表示用グループで回転し、床とTurntableの回転軸は表示の+Zにそろえます。元GLB、編集用頂点、倍率・XYZ移動、GLB/NPZ出力は入力座標のままです。表示の回転を出力へ二重適用しません。方向変更時は視点を初期化し、同じ方向での編集操作中は視点を保持します。

上方向は表示だけの設定ではありません。WSL側は選択方向でVLM用画像をレンダリングし、セグメント前には同じ方向から+Zへ回転します。分割結果の頂点は元の入力座標へ戻して出力します。パーツ生成LLMには物体名と要求文を渡すため、方向の影響は名前推定を介した間接的なものです。入力画面で方向を変えた場合、以前の名前・パーツ構成・分割結果を無効化し、「パーツ構成を作成」からの再実行が必要です。

1. Pythonの `editing.py` がNPZからパーツごとの頂点・面と中心を読み込みます。
2. Pythonの `boundary_blending.py` が選択パーツの境界距離と重みを事前計算し、結果をキャッシュします。スライダーのドラッグ中はThree.jsが同じ中心・倍率・接続グラフ・重みで局所変形まで描画します。毎フレームのPython実行やGLBの再生成は不要です。
3. ドラッグを離すと倍率と移動量をStreamlitへ渡します。Pythonは `follow_connected_parts()`（追従オフなら `scale_parts()`）、`apply_boundary_blend()`、`apply_boundary_motion()` の順に適用します。JavaScript側とPython側の頂点座標の一致を自動テストで確認しています。
4. Pythonで計算したパーツは `st.session_state["part_editing"]["edited_parts"]` に保持します。今後の形状編集処理から利用できます。
5. 接続の情報・基準パーツ・移動量・接続点のずれは `st.session_state["part_editing"]["connections"]` に保持します。「編集後 GLB」には位置補正済みの頂点と、この情報をシーンのメタデータに保存します。接続点の丸印や補助線はGLBの形状へ追加しません。
6. 手動移動は `st.session_state["part_editing"]["offsets"]` に保持します。接続メタデータの `automatic_translations` が自動追従、`manual_translations` が手動移動、`translations` が合計です。GLBの最終頂点と再結合にも手動移動を反映します。
   `following_method`は`each_edited_part_drives_contacts_v1`です。`responses`に発生元ID・接続先ID・単位倍率変化に対する変位係数、`attachments[].planes`に共通面と断面ID、`following_planes`に両側の倍率と移動を含む接続面の法線方向の残差を保存します。互換用の`root_id`は閉鎖・延長の役割であり、追従・なじませの固定点ではありません。
7. なじませの選択ID・割合・距離統計は接続メタデータの `boundary_blending` に保存します。なじませ中の接続点は実際の変形後の境界頂点から計算し、表示の点と診断表の両方へ反映します。

編集元はモデルID・パーツ構成ID・分割ID・NPZ内容で識別します。別の分割結果やCCS補正結果へ切り替えると倍率と移動量を初期化します。
モデル・要求文・向きなどの変更で分割結果が無効になると編集状態も破棄します。ページを再読み込みした場合も倍率は永続保存されません。

入力GLB、分割済みGLB、NPZを上書きしません。元データは保持され、編集済みモデルはダウンロードしたGLBへ保存されます。
なじませ未選択では、接続点が一致しても倍率の異なる境界の幅や形状は一致しない場合があります。通常の編集は独立パーツの表面を変形します。分割断面に蓋を生成する場合は次節のボタンを使います。編集内容によって隙間や重なりが生じることがあります。

## 分割断面を閉じる

「断面を閉じる」は、拡大縮小・自動追従・境界なじませ・手動移動を適用した現在のパーツを使います。未編集でも実行できます。各パーツに別々の蓋を作り、独立したメッシュのまま確認・保存します。ボタンを押すまでは蓋を生成せず、スライダードラッグ中に毎回三角形分割を行いません。

1. 元の全体面と所属IDから、異なるパーツが共有していた辺だけを切断境界として抽出します。取っ手の上下などの閉じた輪郭は個別に処理します。境界が閉じていない、分岐する、非多様体の箇所などは保留理由を表示します。元から存在した開口部は対象にしません。
2. UV・法線用の頂点コピーは、同じ元位置に由来し、編集後も座標が完全一致する場合に限り、この派生メッシュの面インデックスで統合します。元の編集用配列は変更しません。由来の異なる近接頂点の溶接は行いません。
3. 境界を近似平面へ投影し、Shapelyで輪郭の交差・接触・包含を確認します。近い同一平面の内外の輪郭はまとめ、中空パイプでは内側を残す環状の蓋にします。別々の断面は独立に塞ぎます。
4. 「三角形の作り方」で方式を選び、元の3D境界頂点へ適用します。境界頂点を平面へ移しません。初期値は「内点判定のみ（試行）」です。輪郭順A/B/Cを最初の候補とし、投影した三角形の**厳密な内部**に残りの輪郭頂点がある場合だけ候補を不採用にします。辺上の点や投影座標が同じ点は内部に含めません。採用したら中央Bを計算上の輪郭から外し、次の候補A/C/Dへ進みます。不採用なら候補を一つ進めます。候補の凸角・2D面積・3D面積による除外は行いません。元の頂点と輪郭の辺を保持し、採用した三角形の面向きを側面の境界に合わせます。一周して候補がなければ、その断面を保留し、途中の面は追加しません。
5. 「非平面の断面も生成を試す」は初期状態でオフです。オフでは近似平面からの最大距離が、その輪郭の境界箱対角長の2%を超える断面を保留します。オンではこの上限による保留を省き、投影した輪郭から三角形の接続を決めて、元の3D境界へ適用します。境界は平面へ移しません。非平面性の値は、保留した輪郭も含めて診断・保存データへ記録します。投影が交差・退化する断面、内外輪郭を一つの断面として特定できない断面は引き続き保留します。自由な3Dパッチ生成・細分化・平滑化を行う機能ではありません。
6. 蓋と同じパーツ内の面交差をCPUで検査します。新しく追加した蓋を含む組だけを報告し、別パーツの同じ場所に作られた蓋同士は検査しません。診断表示の赤色は保存する色には反映しません。検出しても自動で面を修復しません。

「内点判定のみ」は穴のない単一輪郭での比較試行です。中空の環状断面は内側を誤って埋めないよう保留し、「Earcut（従来）」への切り替えを案内します。初期の閉じた輪郭の抽出と投影輪郭の交差・退化検査は両方式で共通です。試行方式は三角形ごとの凸角と面積の判定を外し、生成後の2D被覆検査も採否には使いません。このため輪郭の外側への張り出し、交差、面積0の面が残る場合があります。3Dで面積0または極小の蓋は除去せず、件数と面番号を診断に記録します。判定の数値許容値は正規化した投影座標の辺からの距離1e-12、極小面の診断基準は元パーツの最大寸法で正規化した外積の大きさ1e-18以下です。

「Earcut（従来）」は既存の三角形分割と2D被覆検査を使い、中空部も保持します。省略された一直線上の境界頂点は補い、側面と辺を共有します。方式を変更すると古い蓋結果を無効にします。実行方式、試行の候補数・内点による不採用数・採用面数、先頭100候補の判定を各断面の`triangulation`へ保存します。追加ライブラリはありません。

「中心から放射状に生成」は、断面ごとに中心Oを1頂点追加し、輪郭順の隣り合う2頂点A/BからO/B/Aの三角形を作る比較方式です。境界が8頂点なら追加する面は8面です。元の面の境界とは逆向きの辺を共有し、取っ手の上下など離れた断面は別々の中心を使います。中心は編集後の各境界辺の中点を辺長で重み付けした平均で、頂点の単純平均や断面の面積重心ではありません。元の境界頂点は動かしません。非平面性が2%を超える場合は、他の方式と同様に「非平面の断面も生成を試す」をオンにします。

放射状生成は全境界辺に必ず面を作るため、開始頂点を変更しても接続は同じです。この方式では開始位置の選択・次へ・初期化を無効にし、他の方式へ戻すと以前の開始位置を使えます。「中心頂点を表示」で黄色の点Oを確認できます。点Oは実際に追加したメッシュ頂点で、GLB・NPZにも保存されます。方式の初期値は従来どおり「内点判定のみ（試行）」です。

中空の環状断面は中心へ集めると穴を塞ぐため保留し、Earcutへの切り替えを案内します。凹んだ単一輪郭では放射状の蓋を生成したうえで、近似平面上の輪郭からの張り出し・覆い残し・面積の重複を診断します。不整合があっても比較用に面を保持し、警告を表示します。投影の面積値は境界箱対角長で正規化した座標で計算し、許容値は`max(投影輪郭面積, 1e-12) * 1e-8`です。3Dの交差も従来どおり検査します。境界が凸でも、非平面の蓋とパーツ本体の交差は別途生じ得ます。診断表では追加頂点数、放射状の投影不整合件数、中心頂点番号と座標を確認できます。

開始位置による違いを比較するには、「開始頂点を変える断面」でパーツ名・断面番号を選び、「開始頂点を次へ」を押します。輪郭の順に1頂点ずつ進み、その場で蓋を再生成します。何度でも押せて、一周すると元に戻ります。「開始頂点を初期化」は選択中の断面だけを最初の位置へ戻して再生成します。他の断面の開始位置は保持します。最初は輪郭内で番号が最小の頂点から、元の面の境界方向に進みます。現在の開始位置・パーツ内頂点番号・最初の3頂点候補を表示し、蓋付きプレビューの黄色の点Aでも位置を確認できます。「内点判定のみ」では表示した3頂点から判定を開始します。「Earcut」では入力輪郭の始点を変更しますが、ライブラリ内部の判定順により三角形分割が変わらない場合もあります。

開始位置の変更は近似平面・元の頂点座標・輪郭順を変更しません。蓋の接続だけを比較します。開始位置は元の境界辺から作った断面IDに対応づけ、編集中の形状が変わっても同じ断面の設定を保持し、入力・分割結果が変わると初期化します。全体の`start_offsets`と輪郭ごとの`loop_key`・`start_offset`・`start_vertex`・`first_candidate`を診断および保存データへ記録します。表示位置は1始まり、保存するオフセット・頂点番号は0始まりです。黄色の点はGLBへ追加しません。開始位置を変えても、生成条件を満たさない断面は引き続き保留します。

「蓋付き表示パーツ」で全体・個別パーツを選択します。英語パーツ名を使用し、「蓋を強調表示」で蓋を青系に、「蓋に関係する交差を表示」で問題の面を赤に表示します。診断表には閉じた領域と境界ループの数、追加面、残る切断境界辺、元からの開口辺、全境界辺、水密性、面向き、交差組数を表示します。2%を超えて生成した断面数と、輪郭ごとの非平面性（%）も確認できます。環状断面は内外2本のループで1領域と数えます。閉じられなかった領域を成功として扱いません。

編集値・追従・なじませ・断面固定移動の条件、または非平面試行の設定が変わると、古い蓋結果を非表示にします。新しい条件でボタンを押して更新してください。表示パーツ、強調色、交差表示、視点だけの変更では結果を保持します。元の分割・補正成果物、編集パーツ、既存の再結合結果とは別に`part_editing["capped"]`で管理します。

- **蓋付きGLB**：パーツごとの独立メッシュ、元の寸法・配置とパーツ色を保持します。蓋も所属パーツの色です。
- **蓋付きNPZ**：パーツごとに`vertices`、`faces`、`source_vertex_indices`、`source_face_indices`、`face_part_ids`、`face_colors`、`is_cap`、`cap_ids`、`is_cap_center`を保存します。元面・元頂点は先頭に保持し、蓋の`source_face_indices`は`-1`、`is_cap=True`です。放射状生成で追加した中心は頂点配列の末尾に並び、`source_vertex_indices=-1`、`is_cap_center=True`です。元頂点の対応値は保持します。他の方式は新しい頂点を追加しません。`metadata_json`はJSON文字列で、`format_version=2`、ID・英語名・配列プレフィックス・編集条件・診断を記録し、`allow_pickle=False`で読み込めます。各断面の`triangulation`には中心の番号・位置・計算法・投影の診断値も記録します。GLBにも中心頂点番号をメッシュのメタデータへ保存します。この派生NPZを元の分割NPZとして編集へ再入力する機能はありません。

個別パーツの閉鎖とパーツ間の再結合は別の操作です。「一つのMeshへ結合」は従来どおり、蓋を加える前の編集用表面を使います。蓋付きパーツからBoolean和を求める場合は、次節の接続維持モードを使います。切断境界を閉じても、元からの開口・非多様体・自己交差があれば全体が有効な立体になるとは限りません。水密表示は辺の位相に関する判定であり、交差がないことや造形適合性の保証ではありません。

追加依存はWindows側だけです。UIに使っているPython環境で更新し、Streamlitを再起動してください。WSLのAPI・モデルは更新不要です。

```powershell
python -m pip install -r requirements.txt
```

`capping.py`と`capping_panel.py`が処理とUIを担当します。テストは二つの切断面、凹多角形、中空断面、一直線上の境界頂点、元の開口部、閉じない切断境界、重複頂点、非平面・交差輪郭、蓋の交差、GLB/NPZ対応、編集後の無効化、開始頂点の巡回、中心からの放射状生成と中心頂点の保存を検証します。

## 接続部を延長してBooleanで統合する

画面の主な操作は「①閉鎖 → ②自由移動 → ③延長 → ④Boolean結合」です。接続を保つための移動制限・編集値の巻き戻しと、5%の延長上限は廃止しました。Windows側の`manifold3d>=3.5,<4`と`rtree>=1.3,<2`を使用します。

### 閉鎖と延長を別々に実行する

1. 「① 断面を閉じる」を押すと、一様スケーリング・自動追従・境界なじませ後のパーツから蓋を作ります。元の頂点・面との対応を保持します。同一境界には、両側で三角形の接続と座標が一致し、向きが逆の蓋を使用します。
2. ①の閉鎖結果を保存し、作成時の形状と診断を表示します。保留した断面や水密性・面向きの問題があっても、作れた形状と理由を表示します。この段階で接続先の探索・延長は実行しません。
3. 「② 閉じたパーツを移動」のスライダーで移動します。閉鎖した蓋も動き、移動のたびに蓋を作り直しません。全体移動は蓋付きパーツを平行移動します。断面固定移動は境界を残す既存の変形なので、断面を動かす確認には「詳細な形状編集設定 → パーツごとの移動方法」で全体移動を選びます。
4. 「③ 接続部を延長する」を押すと、保存済みの蓋と元の接続情報から延長を計算します。蓋を再生成せず、移動後の断面の法線の両方向から受け側へ届く方向を調べます。
5. 子パーツの蓋を先端へ移し、元の境界と先端の間に側面を追加します。移動元の蓋を内部に残しません。中空断面では内外の側面を作り、穴を保持します。各接続の成功・失敗と延長量を個別に表示し、成功した接続の形状を確認できます。
6. 「④ Booleanで統合」を押すと、③で全接続を処理できた閉じたパーツの和をManifoldで求め、内部面を除去します。元の面が分割された場合も元のパーツIDと面番号を引き継ぎます。

蓋と食い込みの設定は一つの折りたたみ欄にまとめています。蓋は中心からの放射状生成、非平面の試行はオンが初期値です。中空断面にはEarcutを使用してください。閉じられない理由は①で確認し、③の失敗時にも移動位置を戻しません。

### 延長量と接続の検査

受け側・付属側は「基準パーツ」と既存の追従グラフで決めます。基準から見た親が受け側、子が付属側です。同じパーツ同士に複数の接続がある場合は同じ役割を使います。取っ手の上下など、追従用の木で採用されなかった接続も検査します。閉じた接続経路では基準からの深さ、同じ深さならパーツIDで役割を決めます。一つの蓋に異なる接続先が混在する場合は延長時に理由を表示します。

断面を近似平面へ投影した境界箱の短い幅を`W`とし、希望する食い込み深さの初期値を`0.01 W`とします。薄い受け側では延長方向にある局所的な壁厚の10%以下に抑えます。

③では蓋の頂点、辺の中点、三角形の中心から受け側へレイを飛ばし、全サンプルが入れる共通の長さを調べます。延長量は「到達までの最大の隙間＋食い込み深さ」です。5%の上限で打ち切らず、現在の受け側全体を含む範囲を探索します。サンプル点が接続先へ到達しない、共通の延長量を求められない場合は理由を表示します。すでに十分な重なりがある場合や、対応する断面が一致したままの場合は延長量0です。

③では交差を生成の停止条件にしません。保存済みの蓋の投影に重なりがある場合も確認用の延長へ進め、先端の三角形が受け側と交差することや、延長後のパーツが自己交差することだけを理由に結果を破棄しません。閉じた断面の対応、有限な座標、退化していない元の蓋など、延長の計算に必要な条件は確認します。

形状を生成・保持した後で、移動後かつ延長前の形状と、延長後の各パーツについて自己交差を診断します。`pre_extension_self_intersection_pair_count`と`self_intersection_pair_count`を比較表示し、延長後の交差Faceを赤く示します。診断そのものが失敗しても生成形状は保持します。パーツ間の食い込みは結合のための重なりとして扱い、この自己交差表示には含めません。②の編集画面での新しい交差の赤色表示は従来どおり別に継続します。

ほぼ同一平面上の隣接Faceを誤って交差と判定しないよう、非共面の三角形同士が同じEdgeを共有する場合は、そのEdge上の接触を内部交差から除外します。同一平面で面積を持って重なる面や、頂点だけを共有して他の領域へ侵入する交差は引き続き検出します。

### 確認・保存

①の閉鎖直後、②の移動中、③の延長後、④の結合後を別々に表示します。①と③からそれぞれ独立パーツのGLB・NPZを保存できます。③で赤く表示した交差Faceも、保存時には元のパーツ色を保持します。GLB・NPZのメタデータには、パーツごとの`self_intersection_pairs`・`self_intersection_face_ids`・件数・延長前の件数を記録します。ブラウザ側は蓋の移動だけを描画し、接続のレイ探索や自動延長を行いません。すべての3D表示はTurntable Rotationです。

Boolean和の入力・出力は水密性、面向き、頂点周りの多様体性、退化面・重複面・自己交差を検査します。空洞を囲む内側の閉じた表面と、分離した立体を区別します。分離した立体が複数残る場合は、一体の印刷用STLのダウンロードを保留します。

③で自己交差があっても④を試すことはできますが、④の入力検査は省略しません。自己交差などが残る場合は④で理由を表示し、③の確認用結果は保持します。

- **Boolean結合GLB**：一つのMesh・ノードで、パーツ色ごとのマテリアルと面の由来を保存します。読み込みソフトによってはマテリアル境界で頂点を複製します。
- **Boolean結合NPZ**：共有頂点を持つ`vertices`・`faces`、面ごとの`face_part_ids`・`face_colors`・`source_face_indices`・`face_kinds`を保存します。`face_kinds`は0＝元の面、1＝蓋、2＝延長側面です。元の面が細分化された場合は元の面番号を引き継ぎ、生成面の`source_face_indices`は`-1`です。`input_face_indices`・`cap_ids`・`metadata_json`にも対応と編集条件を記録します。`allow_pickle=False`で読み込めます。
- **延長したパーツNPZ**：個別パーツの閉鎖NPZに`is_extension`を追加し、延長側面を識別します。`source_vertex_indices=-1`の生成頂点でも、中心頂点だけを`is_cap_center=True`にします。
- **印刷用STL**：「1座標単位を何mmにするか」を掛けた二進STLです。外形寸法をmmで表示し、STLのfloat32精度へ変換した形状も検査します。STL自体は単位・色を標準化しないため、スライサーでもmmとして寸法を確認してください。

形状検査は肉厚、強度、材料、プリンター条件を判定しません。診断の`printability="not_assessed"`は、この造形条件を未評価であることを示します。スライサーの層表示も確認してください。

移動量・移動方法を変えた場合は③・④だけを無効化し、①の閉鎖結果を保持します。食い込み深さの変更も③からやり直します。倍率・なじませ・蓋の方式などで閉鎖形状が変わった場合は①からやり直します。新しい分割結果へ切り替えると各段階を初期化します。従来の比較用操作は「従来の閉鎖・再結合を比較（詳細）」へまとめています。

`connection_overlap.py`が接続の検査と延長、`boolean_union.py`が和と出力、`solid_panel.py`が設定・結果管理を担当します。ブラウザの閉鎖形状プレビューは`scale_component/src/connection_constraints.js`の`preview_only`経路です。旧方式の互換用ヘルパーにある接続制限はUIから呼び出しません。

## ボタンによるメッシュの再結合

スケーリング・位置追従・境界なじませ・X/Y/Zの手動移動を適用した後の形状を使います。結合はボタンを押した時点の結果として保持し、スライダー・基準パーツ・追従設定・なじませ設定を変えたときは古い結合結果を非表示にします。結合ボタンをもう一度押して更新してください。接続点の表示切り替えでは結合結果を保持します。

`rejoining.py` が以下の処理を行います。

1. NPZの `source_vertex_indices` と `source_face_indices` で、各パーツの頂点・面を元モデルへ対応づけます。対応情報が欠ける場合はボタンを無効にします。
2. 元の頂点位置が同じだったコピーについて、編集後も位置が一致するものを統合します。数値誤差としてモデル全体の対角長の `1e-10` を許容します。元の対応が異なる近接頂点を距離だけで結合しません。
3. 元は辺を共有していた異なるパーツの間で、境界が離れた部分に三角形を追加します。位置追従のために選択した接続グラフだけでなく、元の共有境界全体を使います。UVや法線用に座標が完全一致した元頂点は、既存の接続検出と同様に同じ位置として扱います。
4. 接続帯の両側に既存面と逆向きの辺を作り、面の向きをそろえます。3パーツ以上の接点に生じた、同じ元頂点由来の小さな閉じた境界には接続面を追加します。
5. 元の面は順序・位置・パーツ色を維持します。追加した接続帯の2三角形には、隣接する両側の色を1枚ずつ割り当てます。接点の補助面も隣接パーツの色を継承します。

確認用の処理です。面の交差や重なりは修正しません。一般的な穴埋め、元形状の開口部の閉鎖、ブーリアン和は行いません。3面以上が共有する曖昧な元境界には橋渡し面を自動生成しません。頂点の統合で不要になる接続面や面積ゼロの接続面は追加しません。

「Mesh数：1」は一つの頂点・面配列にまとめたことを表します。元から離れたメッシュ間に新しい接続は作らないため、連結成分が複数残ることがあります。画面に成分数と元面・接続面の数を表示します。水密化や3Dプリントへの適合を保証する処理ではありません。

- **結合後GLB**：glTF上のMesh一つ・ノード一つとして保存します。同じ頂点座標の配列を使い、パーツ色ごとに面をマテリアルのグループへ分けます。面色を頂点で平均して混ぜる処理は行いません。読み込みソフトによっては、このグループを別々の形状として扱う場合があります。
- **結合後NPZ**：統合済みの `vertices`、`faces`、面ごとの `face_part_ids`、`face_colors`、`source_face_indices`、`is_bridge` を保存します。追加面の `source_face_indices` は `-1`、`is_bridge` は `True` です。Pythonで結合した頂点の共有関係をそのまま読み込めます。

元の入力・分割ファイルと、編集中の独立パーツは上書きしません。GLBとNPZは画面からダウンロードしたファイルへ保存されます。

## 起動と変更箇所

通常のStreamlit起動方法は[README.md](README.md)と同じです。起動中なら画面を再読み込みしてください。
断面閉鎖を使う場合は、上記の手順でWindowsのPython依存を更新します。WSL側のファイル更新、Node.jsのインストール、フロントエンドの再ビルドは通常の起動に不要です。

`scale_component/dist/` にビルド済みJavaScriptとHTMLを同梱しています。ブラウザUIのソースを変更するときだけ、Node.jsとpnpmで再ビルドします。

```powershell
cd scale_component
pnpm install --frozen-lockfile --store-dir node_modules/.pnpm-store --node-linker hoisted --package-import-method copy
node build.mjs
node --test tests/connection_solver.test.mjs
node --test tests/editor_args.test.mjs
node --test tests/turntable_controls.test.mjs
node --test tests/boundary_blending.test.mjs
node --test tests/orientation.test.mjs
node --test tests/translation_frames.test.mjs
node --test tests/overlap_highlights.test.mjs
node --test tests/connection_constraints.test.mjs
```

`src/editor.js` が動作、`dist/index.html` がレイアウト、`build.mjs` がJavaScriptと第三者ライセンス一覧の生成を担当します。
依存はロックファイルで固定しています。Three.js（MIT）、Streamlit Component Library（Apache-2.0）、Lucide（ISC）のライセンスと依存ライブラリの通知を `dist/THIRD_PARTY_LICENSES.txt` に同梱しています。

更新前のWindows UIが移動量や範囲を送らない場合も、旧データの表示は継続できます。その場合、移動スライダーを無効にしてUI再起動の案内を表示します。Windows側のStreamlitを停止・再起動してから、ブラウザを再読み込みしてください。接続方針の新しいLLM出力を使う場合は、[WSL側の更新](../ip-object-name/PREPARATION_API.md)も必要です。

JavaScriptはビルド内容のハッシュを付けたURLで配信し、Python側のコンポーネント名にも同じハッシュを使用します。ビルド後にWindows UIを再起動すると、新しいコードを読み込みます。

参照：[Three.js OrbitControls](https://threejs.org/docs/#examples/en/controls/OrbitControls)、[Streamlit components](https://docs.streamlit.io/develop/concepts/custom-components/intro)。
